## How to work (owner, 24 October 2026: token use was too high)

Measured on 23 October: the lead session and each slice agent re-read 170–650 M tokens, because every step re-sends the
whole history (350–450 k by the end). So:

- Start a fresh session after each merged slice; trust `RESUME.md` and this file instead of re-reading.
- One fresh agent per job with a short brief. Never resume a big agent for a small job (main merges, small fixes):
  use a fresh Sonnet or Haiku agent instead.
- Split long slices into pieces of a few hours, each pushed with a hand-over note.
- At most 2–3 agents at once (the container has 4 CPUs). E2E under `flock /tmp/ebmr-e2e.lock`, held only while a run
  executes.
- Watch only the PR in flight; no check-ins while an agent is working; a "nothing new" wake costs a whole context read.
- Before a PR goes up, run the affected E2E groups locally (`EBMR_E2E_GROUP=<group>`), not only the slice's own specs:
  cross-slice collisions (seeds, line choice, migration order) are what failed CI on 23 October.
- CI logs: download the blob/output artifacts with `gh api repos/maglesT/ebmr/actions/artifacts/<id>/zip` and read
  `report.jsonl` / `error-context.md`, instead of long log tails.

## RunPod CI runner plan (owner chose it on 24 October)

Not on the hosted-demo server (it would slow the demo and run branch code next to its keys). A separate RunPod CPU pod,
5 GHz, 16 vCPU, at least 32 GB RAM, a 100 GB volume at `/workspace`, SSH on.

Owner's part (instructions given in chat):
1. Install `sudo curl git tmux build-essential` and PostgreSQL 16 (PGDG apt repository); create user `ci` with
   passwordless sudo; `/workspace/runners` owned by `ci`.
2. Register six runners `pod-1` … `pod-6` with label `ebmr-pod` from GitHub → Settings → Actions → Runners → New
   self-hosted runner, each in `/workspace/runners/pod-<n>`, started in tmux with `./run.sh` (no systemd in a pod).

Our part, one PR, after the owner says "runners are up":
- `runs-on: ebmr-pod` for the test shards, the E2E groups and the golden batches; light checks stay on GitHub.
- Each job starts its own PostgreSQL 16 cluster in its workspace on a free port (`initdb` + `pg_ctl`, no systemctl), and
  the golden job its clock-library cluster the same way; `EBMR_PG_ADMIN_URL` per job.
- `playwright install --with-deps chromium` works with the sudo user; keep `PLAYWRIGHT_BROWSERS_PATH` per runner.
- A switch to fall back to GitHub-hosted runners (a repository variable, e.g. `CI_RUNNER`), for when the pod is stopped.
- Prove it with one full CI run on the pod before merging.
