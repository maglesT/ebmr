# Run-time, planning and plant gaps (owner's MGL-SR-BL report, demo commit be637a7)

The owner built a bilayer metformin SR and glimepiride tablet on the standalone demo (`EBMR_DISCONNECT=1`) using only
the screens, then ran a sandbox and a GMP batch; both stuck. This plan covers the run-time, planning and plant items
(G1 to G12). The designer items (D-0 to D-8) belong to another session. One small PR per group; the lead audits.

Rules: a refusal needs a quoted binding clause or a named engine or record-integrity need; records say what was done;
every fix works in every edition (Tablets, Capsules, Injectables, API); tests carry their control IDs.

| Gap | Root cause in the code | Fix | Basis |
|---|---|---|---|
| G1 (items 1, 18) | A time the block computes (TB-07 blend time) is stored and judged at the PERFORMED attempt; the database allows a block-computed value only in its own step's PERFORMED or PREPARE row (EBMR-EXE-126; DI-33, INV-25). The step screen's action list dry-runs that attempt (`engine/actions.ts`), so a breach of a blocking tier greyed out the signature with the reason "EX-2 unresolved", yet EX-2 existed only in the dry run: it was never stored and could take no deviation. The entry text "within limits" judged only the block's own time window, not the parameter's tiers. | The signature stays offered when only the attempt's own finalisation would block it (every block computing at PERFORMED: TB-01, TB-04, TB-07, TB-08, TB-18, G-07, G-08). The signing prepares the attempt, which stores the exception (PREPARE row), and is refused with its reason; nothing is signed. The exception then shows on the step and takes its deviation. TB-07's `withinLimits` also checks the parameter's tiers, so the entry reads "outside limits" at once. Storing at the entry was tried and dropped: it needs the database guard loosened. | PR-08 (the tier decides what happens next); records say what was done. |
| G2 | `apps/tablets-web/src/app/disconnected.tsx` puts `/quality/deviations` in the web-only off list, so the only screens that raise a deviation-lite and link it to a batch show "Not part of Batchwright". The server keeps `raiseDeviation` and `linkDeviation` served, and ATTACH_DEVIATION on a GMP batch needs that record (recipe-core 0601, EBMR-EXE-600). | Keep the deviations list and its detail page (raise, link to a batch) on when disconnected. Reclassify and cancel stay off, as on the server. Update the disconnect docs and tests. | It works, so it is shown (owner: "shows only what works"); PR-49. |
| G3 | Tablets 0844 redefines `recipe.refusal_problem` with `ENG\|G<nn>\|TB<nn>`. | G4 (items 14, 15) | `PlanningPage.tsx` keeps the planned batch only in React state. No read lists planned batches (`recipe.stub_batch` PLANNED), and no route cancels one. The same IN-30 check and message run at planning. | IN-30; every act has a route and a screen (decision 0025). |
| G5 (items 22, 23, 25) | `platform/http/errors.ts` maps only errors that carry an EBMR code; raw 23514, 23505 and 23502 errors become a 500. An explicit refusal in `plant.record_equipment_event` and `site.receive_lot`. The form marks the reference required for QUALIFIED and REPAIRED. Messages on the regexes; problems shown only after a send. Sweep the plant `define*` routes. | Record integrity (the DB checks stay); a 500 is a defect. |
| G6 (item 24) | `CalcField` has no `decimals`. The entry summary prints the full quotient (`block-version.ts` valueText).
